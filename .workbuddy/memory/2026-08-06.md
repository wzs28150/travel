# 2026-08-06 工作日志

## 服务器增量更新（老库升级，保留数据）
- 用户要在「已有数据的老库」上更新到新版本，问如何增量更新。
- 结论：本项目后端 `server/src/index.js` 的 `ensureSchema()` 已幂等处理老库升级——先查 `information_schema` 判断 `users` 是否有 `is_admin` 列、无才 `ALTER ADD COLUMN`；`storage_requests` 用 `CREATE TABLE IF NOT EXISTS`；出错仅告警不中断。**老数据零丢失**，无需手动 SQL。
- `deploy/docker-compose.yml` 的 mysql 用命名卷 `mysql_data`，`docker compose up` 不删卷 → 数据天然保留；`init.sql` 仅在卷首次为空时执行，老库不会重跑（这正是当初漏 is_admin 的根因，由 ensureSchema 补偿）。
- 已交付 `deploy/update-schema.sql`（幂等手动增量脚本，供透明/可控使用；后端自动做等效逻辑）。
- **增量更新标准流程**（勿删栈/勿删 mysql_data 卷）：
  1. 备份：`docker exec travel_mysql mysqldump -uroot -prootpass travel_db > backup.sql`
  2. 传 `deploy.tar.gz` 到服务器解压 → `docker load -i travel-images.tar`
  3. 注入管理员：`ADMIN_USERNAME=admin ADMIN_PASSWORD='强密码' docker compose up -d --force-recreate`（只重建 frontend/backend，保留 mysql 卷）
  4. 验证：`docker logs travel_backend`（看 `[schema]` 日志）、`curl :8090/api/health`、用 admin 登录 `/admin.html`
- ⚠️ **端口坑**：若服务器系统自带 MySQL 占 3306，docker 的 mysql 容器 `3306:3306` 会冲突 → mysql 起不来 → backend `depends_on: service_healthy` 不满足 → 502。修复：改 compose 的 mysql `ports` 为 `3307:3306`（容器内仍是 3306，DB_PORT 不变）。
- ⚠️ **管理员**：`deploy/docker-compose.yml` 的 `ADMIN_USERNAME/ADMIN_PASSWORD` 默认空，部署必须注入，否则老库无管理员、后台登录报"无管理员权限"。
