## 🐞 紧急修复：管理员登录失败（admin/admin123456 提示"账号或密码错误，或无管理员权限"）

**根因**：当初加管理后台功能时，`deploy/init.sql` 的 `users` 建表语句**漏写了 `is_admin` 列**（只写进了代码与记忆，没落地到建表脚本）。连锁反应：
- `server/src/index.js` 的 `bootstrapAdmin()` 启动即 `SELECT ... WHERE is_admin=1` → 该列不存在 → SQL 报错被 catch 吞掉 → 永远建不出管理员 → 登录必失败。
- 后端**不**自建表（无 `CREATE TABLE`/`.sync()`），完全依赖 `init.sql`，所以连全新部署也建不出管理员。
- 运行中的老库（mysql_data 卷非首次启动）还同时缺 `storage_requests` 表。

**修复（commit `8aa40c1`，已本地 commit，push 因沙箱网络被挡）**：
1. `deploy/init.sql`：`users` 表补 `is_admin TINYINT NOT NULL DEFAULT 0`（让全新部署正确）。
2. `server/src/index.js`：新增 `ensureSchema()` 启动自检（幂等：`information_schema` 查 `is_admin` 列，缺则 `ALTER TABLE ... ADD COLUMN`；`CREATE TABLE IF NOT EXISTS storage_requests`），在 `bootstrapAdmin()` 之前 `await` 执行。这样**任何已有库重启后端即可自动痊愈**，无需手动跑 SQL。
3. 运行中的库已手动无损益补列 + 建表并重启，验证 `POST /api/auth/admin-login` 用 `admin/admin123456` 返回 `code:0 登录成功`、`is_admin:1`。

**经验**：凡改 DB schema，必须同步改 `init.sql` 的建表语句（不能只改代码）；老库升级靠后端启动自检兜底，别只依赖 init.sql（它只跑首次）。

### ⚠️ 沙箱 docker build 代理坑（新增）
- 本沙箱 shell 的 `HTTP_PROXY/HTTPS_PROXY` 仍指向已死的 `127.0.0.1:11888`，导致 `docker compose build` 拉取基础镜像时走死代理报 `proxyconnect ... 127.0.0.1:11888 ... refused`。
- **修复**：构建前清掉这两个变量 —— `env -u HTTP_PROXY -u HTTPS_PROXY docker compose build backend`（基础镜像已在本地缓存，不联网也行）。注意这是 shell 环境变量，不是 git config，与之前清的 git 全局代理是两回事。
