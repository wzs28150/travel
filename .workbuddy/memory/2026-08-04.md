## 存储扩容改为「申请→管理员审批」闭环（commit `87a73a2`，已 push origin/main）

用户质疑原「点按钮无条件 +2GB 扩容」太随意，决定改为申请审批闭环（客户端不能自行加空间）。

### 后端
- 删除 `PUT /auth/storage/expand`（无条件 +2GB），新增：
  - `POST /auth/storage/apply`：校验 `requestedGb`(1~500)、同用户已有 pending 则 409、插入 `storage_requests`(status=pending)。
  - `GET /auth/storage/request`：返回该用户最新一条申请状态（前端显示「审核中」）。
- 新增 `server/src/routes/storageRequests.js`（admin 路由）：列表（可按 status 过滤，JOIN users 取昵称/上限）、`PUT /:id/approve`（users.storage_limit += requested_gb*GB，标记 approved、记 admin_id）、`PUT /:id/reject`（标记 rejected + admin_note）。`router.use(auth); router.use(requireAdmin)`。
- `server/src/index.js` 挂载 `/api/admin/storage-requests`。
- `deploy/init.sql` 新增 `storage_requests` 表（含 FK 到 users）。

### 前端
- `api/http.js` 新增 `storageRequestApi`（list/approve/reject，携带 admin token）。
- 新增 `admin/components/AdminLayout.vue`（共享后台布局：侧栏「👥 用户管理」「📦 存储扩容」+ 顶栏昵称/退出，onMounted 校验 admin token + loadMe）。
- 新增 `admin/views/StorageRequests.vue`（审批页：tab 筛选 pending/approved/rejected/all；pending 行「通过/拒绝」）。
- `admin/views/Users.vue` 重构为复用 AdminLayout（上移 sidebar/topbar/logout 逻辑）。
- `admin/router.js` 增加 `/storage-requests`。
- `views/Mine.vue`：「申请扩容」弹窗（快捷 [5,20,50,100]GB + 自定义 1~500 + 理由），无 pending 时显示「审核中 · +XGB」tag；移除原无限点 `expand()`。

### ⚠️ 沙箱构建环境坑（重要，复用）
- 本沙箱 Windows node v22.22.2 跑 `vite build` 多入口（main+admin 双 input）稳定崩溃：worker 线程 `Cannot read properties of undefined (reading 'includes')`，vite reporter 自身崩溃吞掉真实错误；连 git 基线双入口也崩 → 与代码无关，是沙箱 vite v6.4.3 + Windows node 的 bug。
- **解决方案**：用 Docker 容器内 Linux node 构建。`docker compose build frontend backend`（容器内正常），再 `docker compose up -d --force-recreate`。
- 单入口（仅 main 或仅 admin）本地构建 OK，双入口同时必崩。排查时用 `vue/compiler-sfc` 单独 parse/compileScript/compileTemplate/compileStyle 校验 SFC 均 OK，可排除代码错误。

### 部署
- 已 `docker save travel-frontend:latest travel-backend:latest -o deploy/travel-images.tar` + `tar -czf deploy.tar.gz deploy`，本地 3 容器（travel_frontend/backend/mysql）均 Up；新接口验证：/api/health 200、/api/auth/storage/apply 401(未登录)、/api/admin/storage-requests 401(非管理员)、/admin.html 200。
- **⚠️ 生产服务器已有库需手动建表**：`storage_requests` 表（见 `deploy/init.sql`）。`init.sql` 只在全新 `mysql_data` 卷首次启动挂载时执行；若服务器此前已起过 mysql 容器（卷已建表），改动不会自动生效，需在服务器 MySQL 手动执行 `CREATE TABLE storage_requests ...` 否则审批接口会因缺表报 SQL 错误。
